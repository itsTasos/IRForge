# Coverage and operational limitations

- User-mode monitoring can lose coverage and is not equivalent to production EDR. Administrators can stop the program. No stealth, persistence, drivers, uploads or automated response exist.
- Live ETW requires appropriate tracing privileges, normally an elevated console. Sessions are limited system resources. IRForge never reuses or stops another application's session. A force-kill or OS shutdown deadline can leave its own session until explicitly stopped by an administrator or reboot. Normal Ctrl+C and timed stop clean it up.
- ETW schema/TDH availability varies by Windows version. Missing optional fields stay null, required PID decode failures are counted. Image names may be only basenames; full image path enrichment can fail. Short-lived and protected processes may exit before creation-time/path enrichment; ancestry then remains unknown. Exit creation times are resolved from event-time lifecycle context, not guessed from the currently reused PID.
- TCP is a polling snapshot, not packets or a guaranteed connection-establishment feed. Short connections between snapshots can be missed; listening entries are observations, not outbound activity. An established row cannot prove the initiator or C2. IPv4/IPv6 table queries and owner-time queries are separate OS snapshots, not an atomic transaction. A newly reused owner detected after snapshot start is rejected, but loss of ETW lifecycle events still lowers attribution coverage. UDP remote peers, DNS, reputation and firewall analysis are absent.
- Native registry observations always have actor_pid=null. Same-path correlation is an inference about related artifacts, never writer proof. Only current HKCU and HKLM Run/RunOnce views and direct service ImagePath/Start/Type are monitored. SYSTEM is shared across WOW64 views. Unloaded user hives, scheduled tasks, Startup folders, IFEO and Winlogon are excluded. Ancestor notifications can be noisy and 250ms coalescing / five-second reconciliation can miss a change reverted between scans. Access/race failures preserve the last successful baseline and report degradation.
- Path comparison is lexical, case-folded and conservative. Only quoted or unambiguous absolute drive-letter `.exe` commands qualify for weak linkage. Environment-variable expansion, aliases, short names, junctions, UNC/device paths, hard links, shell wrappers and unquoted paths with spaces are not resolved. User-writable classification recognizes Users and Temp directories, not actual file-system ACLs. This reduces unsupported claims but creates false negatives and false positives.
- Encoded-command indicators use bounded substring predicates, so unusual abbreviations, tabs, escaping and punctuation may evade the default rule. Encoded arguments and Office automation can be legitimate. Public addressing is not threat intelligence. Address classification identifies common special ranges but is not a complete evolving IANA registry or route-reachability assessment.
- Scores are capped sums of distinct active rule IDs, not calibrated probabilities. Default thresholds may need tuning. New standalone Run values score 20 and do not alert at the default medium threshold unless another rule also matches. Events remain logged. A service path finding scores 35. Configure a lower alert threshold to surface these signals individually.
- Context is bounded to 4096 events/300 seconds by default. Active scores use the latest 120 seconds, and process starts older than retention are discarded; later network attribution can be unknown for long-running processes. Overflow eviction is visible. Rebuilding bounded history prioritizes correct late-event reconciliation over high-volume throughput. This release is intended for supervised small-lab use, and high-rate ETW / slow disks can cause queue drops. No throughput guarantee is made.
- Replay IDs and results are stable for the same arrival sequence. Reordered events within retained event-time windows converge on the same current incident; intermediate alerts can differ. Events arriving older than the watermark's active/retention windows cannot revive expired evidence. Wall-clock adjustment in live mode can affect cross-source windows.
- Logs can include secrets in command lines and registry values. Output directories receive a private protected DACL for current user, SYSTEM and Administrators. Choose a fresh folder; existing contents are refused. IRForge does not redact secrets. Administrators/backup privileges can still read logs. Line writes and atomic health replacement prevent interleaving, not a guarantee against abrupt power loss or disk failure.
- Forced console closure, storage hangs, and external termination may exceed graceful shutdown bounds. Runtime collection failures stop by default; `--allow-degraded` preserves remaining sources and health warnings. Config-disabled sources visibly reduce coverage. All-disabled mode collects nothing and should only be used for configuration checks.
- MinGW Debug/Release CI is configured but a hosted run requires pushing the repository to GitHub. Visual Studio is not required. The local build/test report states which native/live tests actually ran. Elevated registry mutation acceptance requires a dedicated authorized Windows VM; no registry-mutating test is run automatically on the user's machine.
- Incident `open`/`expired` state is maintained in memory. The saved alert log contains threshold/escalation snapshots, not a complete incident-state journal; expiration, analyst dismissal, confirmation and resolution are not persisted. A past alert with status=open does not establish that the incident is still active, and there is no automatic clean/infected host verdict.

# Automated and supervised testing

Configure and run `scripts/build.ps1` for MinGW x64 Release, or `scripts/build.ps1 -Configuration Debug` for a separate MinGW Debug build. Visual Studio is unnecessary. The legacy `-MinGW` switch is still accepted but is no longer required. If the compiler is outside PATH, use `-ToolchainDirectory D:\Tools\w64devkit`; the script also detects `C:\w64devkit` when available. Debug builds reuse previously fetched Release dependency sources when present. Catch2 is pinned to 3.7.1; CTest discovers assertion-backed cases and adds CLI validation/replay tests. No live ETW or registry writes are required in CI.

Pure tests cover bounded queue FIFO, drops, waking/draining shutdown, schema/null/Unicode roundtrip, invalid config, timestamp validation, address and conservative path classification, typed Registry add/modify/delete/key diff and malformed values, selected service context, TCP baseline/dedup/state changes/removal/PID reuse/failed query preservation, rule validation and malformed JSON/duplicate IDs, missing fields, case-insensitive positives/negatives, all six built-ins, complete correlation, wrong/unknown owner rejection, reused PID isolation, order-tolerant event-time reconstruction, weak/standalone Registry evidence, score clamping, active expiration and history eviction. Fixtures are synthetic and contain no executed payloads.

Use a disposable **Windows 11 x64 VM you own or are authorized to test** for full collector acceptance. Build Release, open an elevated PowerShell terminal and start:

```powershell
./scripts/run_demo.ps1 -DurationSeconds 120
```

In another VM terminal launch and close Notepad and `cmd.exe /c exit`, including repeated cycles. Check process_start/process_exit, payload PID, creation time where available, and initial_enumeration on rundown. A fast command can exit before enrichment; unknown creation time is expected. Review monitor-health.json for decode errors, ETW event/buffer loss, queue drops, and active sources. Stop with Ctrl+C, repeat with a timed run, and verify no `IRForge-...` session from these runs remains using the read-only `logman query -ets` command. Do not stop unrelated sessions.

For TCP, run a benign loopback HTTP server on both `127.0.0.1` and `::1` where IPv6 is enabled. Keep a connection alive longer than two polling intervals from a known client process. Check local/remote ports, owner PID, family, first_snapshot=false, and a later disappeared observation. An easy fixture-only alternative is the automated network diff test; it does not verify native table enumeration. Explain explicitly that shorter connections can be missed. Do not use a public destination merely to generate a suspicious alert.

For Run/RunOnce, only in the dedicated VM, use a second console to save any preexisting uniquely named `IRForgeDisposableVMTest` value, add a benign quoted executable string, modify it, and remove/restore it in `finally`. IRForge itself never writes these keys. Verify before/after typed payloads and actor_pid=null for all three changes, no initial-baseline additions, and correct view label. Repeat for deletion/recreation of a disposable test key only if its setup is isolated. Service add/modify/delete assertions use synthetic snapshots and replay; do not install a real service simply to exercise the heuristic.

Run non-elevated `monitor --duration-seconds 3 --output NEW_FOLDER` to verify explicit ETW failure and nonzero status; then repeat with `--allow-degraded` and a separate folder to verify remaining source coverage plus DEGRADED diagnostics. A restricted sandbox can deny ETW even if the host account is an administrator; report this environment distinction. Config-disabled collectors must be reflected in health. Test output errors with an existing nonempty directory and verify it is preserved.

For deterministic replay, run the suspicious fixture twice to different empty directories and compare events.jsonl and alerts.jsonl byte-for-byte. Expect high (60) then critical (100) incident escalation. Benign replay should produce zero alerts, PID reuse must not earn CORR-001, and unrelated registry fixture should remain standalone with null writer. Session metadata deliberately omits replay wall-clock stop time.

Measure CPU/memory with PowerShell `Measure-Command` and `Get-Process` during a clearly stated test duration. A short idle smoke test is not an EDR benchmark; record measured values and environment rather than extrapolating throughput. See implementation-report.md for actual commands, outputs and unexecuted manual acceptance gates.

`scripts/smoke_native.ps1` performs a ten-second read-only native loopback test, asserting both address families, the test shell's owning PID, and disappearance. It creates no Registry values. `scripts/smoke_shutdown.py` optionally uses Python's standard library to send Ctrl+C to a private hidden console and verify flushed metadata and bounded exit. Python is only a developer-test dependency for that optional script; IRForge itself has no Python runtime dependency. These tests still require elevated tracing privileges to validate successful ETW startup. Running them outside a restricted sandbox removes sandbox access restrictions but does not grant UAC elevation.

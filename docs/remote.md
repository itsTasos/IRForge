# Optional remote collector

Transport includes certificate-bound `/v1/heartbeat` health every 30 seconds and retry jitter with a bounded 1–60 second backoff. JSON bodies above 4 KiB may use native Windows XPRESS_HUFF compression when it reduces size. The receiver validates the declared expanded size against the 1 MiB limit before allocation and rejects malformed/bomb frames. It does not accept arbitrary HTTP compression or chunked bodies. Original native IPv6 scope IDs remain in evidence; STIX address values omit the zone identifier.

IRForge uses pinned Qt 6.8.3 Network with Windows Schannel, the native Windows TLS implementation. TLS 1.2 or newer, private CA validation, hostname verification and client certificates are mandatory. There is no verification bypass. Collector identity can additionally be pinned by SHA-256. No OpenSSL or Visual Studio installation is required.

The equivalent versioned contract is HTTP/1.1 POST with `application/json`, Content-Length, no chunked encoding, 16 KiB headers and 1 MiB JSON body. `/v1/batch` accepts schema-1 batches containing 1–100 schema-v2 event or incident metadata packets. Each packet binds `agent_id`, `host_id`, `session_id`, positive monotonic `sequence`, `kind` and `data`. `/v1/query` offers paginated read-only evidence queries and incident detail. `/v1/enrollment` changes certificate enrollment only for explicitly enrolled admin certificates. Unknown endpoints reject. No file extraction, deployment or command endpoint exists.

Enrollment maps the SHA-256 certificate fingerprint to one agent, host and role (`agent`, `viewer`, `admin`). Viewer reads require an explicit permitted host filter. Agent certificates cannot query or change enrollment. Revocation is checked on every application request. CA/expiry/hostname checks occur during TLS; leaf-fingerprint enrollment restricts otherwise valid certificates. Protect the operator CA key offline; rotate by enrolling the replacement fingerprint, testing it, then revoking the old one. This is a single-operator fleet, not a multi-tenant product.

Supply your own CA PEM and identity PFX. Encrypted PFX passwords are read from the current Windows account's Credential Manager target named by `credential_target`; no password appears in argv/config/logs. A service has a different credential context. Empty passwords are supported for disposable tests only. Do not commit private keys. Configuration templates are `config/collector.example.json` and `config/remote.example.json`.

1. Provision distinct agent and analyst certificates with clientAuth; server certificate with serverAuth and correct DNS SAN. Restrict private-key ACLs to the service account and administrators.
2. Run `irforge_collector enroll --db COLLECTOR_DB --fingerprint SHA256 --agent-id AGENT --host-id MACHINE_GUID --role agent --confirm` before serving. Enroll a separate viewer with `--allowed-hosts HOST1,HOST2` for queries and a separate admin for live enrollment changes.
3. Run `irforge_collector serve --config COLLECTOR_CONFIG`. Loopback is the default. A non-loopback bind requires `--allow-network`; restrict Windows Firewall inbound port to your two authorized test VMs and analyst IPs. No firewall rule is created automatically.
4. On each endpoint run `irforge remote configure --db AGENT_DB --config CONNECTION_CONFIG --agent-id AGENT --confirm`. Enable `remote.enabled` with `remote.config_path` in that endpoint's monitoring configuration. The sender starts only when explicitly enabled. `remote send` delivers one queued batch; `remote query` uses a viewer/admin identity.
5. Use the collector's authenticated local pipe `IRForge.Collector.v1` with the GUI on the collector host. Host filters isolate incoming records. Endpoint source observations remain source-reported evidence, even though their transport identity is cryptographically authenticated.

Local evidence commits first. Optional spool failures are visible and cannot veto the local evidence transaction. Spool defaults: 10,000 records, 128 MiB and seven days. Queue overflow/expiry produces explicit loss records. Delivery is at least once, bounded by batch bytes/count; the receiver only acknowledges after durable commits. Retries deduplicate on agent/session/sequence; missing sequence intervals become coverage gaps. A stale packet never moves the acknowledgement backwards. Commands/Registry bytes/raw provider XML are redacted by default, and files are never transmitted. Incident explanations remain metadata. Review path/host/IP disclosure before enrolling.

The separately maintained local integration suite exercised two enrolled identities over real native loopback TLS, including roles, revocation, durable retry and negative certificates, using ephemeral PKI and labelled synthetic observations. It did not modify certificate stores. Tests and private PKI are excluded from the release repository. The two separate Windows VM deployment gate is **NOT RUN** in this environment.
